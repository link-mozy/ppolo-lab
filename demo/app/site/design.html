디자인 정의서

이 문서는 PPOLO의 UI/UX 기준을 한눈에 확인하기 위한 CSS 기반 디자인 정의서 초안입니다. 목표는 화면마다 다른 표현을 쓰더라도 색·간격·상태·정보 우선순위가 흔들리지 않도록 만드는 것입니다.

공개 경로: design.html 검토 대상: UI / UX 확인 포인트: 구조 · 플로우 · 부족한 내용

핵심 요약

운동 기록과 경쟁을 같은 서비스로 느끼게 하되, 화면은 목적별로 분리한다.

홈은 현재 상태를 빠르게 읽는 곳, 운동 기록은 입력과 확인을 분리하는 곳, 경쟁은 시작 전 대기와 실시간 측정을 분리하는 곳, 워치는 최소 리모컨으로 동작하는 곳입니다.

1. 색과 톤짙은 네이비 배경 + 청록/블루 액센트로 활동적인 인상을 유지합니다.
2. 정보 구조상단 요약 → 핵심 카드 → 세부 목록 → 행동 버튼 순서로 읽히게 합니다.
3. 상태 문구측정 대기 / 측정 중 / 측정 완료 / 경쟁중 같은 상태를 문서 전체에서 일관되게 씁니다.

1. 디자인 토큰

색 / 타이포 / 간격 / 라운드 / 그림자

화면마다 동일한 룩을 유지하기 위한 공통 규칙입니다.

배경 #07111f 계열을 기본 배경으로 사용합니다.
액센트 버튼, 강조 수치, 상태 라벨은 블루/청록 계열을 사용합니다.
텍스트 제목은 밝게, 설명은 muted 톤으로 내려 읽기 흐름을 만듭니다.
패널 카드는 반투명 패널을 기본으로 하고, 구분선으로 정보 덩어리를 나눕니다.

2. 타이포그래피

제목은 짧게, 본문은 충분히, 숫자는 크게

  • 큰 제목은 화면 목적을 즉시 드러내는 단어만 사용합니다.
  • 설명 문장은 2줄 안팎으로 유지해 읽는 부담을 줄입니다.
  • 시간, 거리, 순위 같은 숫자는 카드 안에서 가장 먼저 보이도록 키웁니다.
  • 영문 상태 키는 내부 문서에서만 쓰고, 화면에는 한국어 상태명을 우선 노출합니다.

3. 컴포넌트 규칙

모든 화면에서 반복되는 요소

  • 상단 제목 + 설명 + 상태 칩 조합
  • 핵심 KPI 카드 3개 정도의 압축 요약
  • 행동 버튼은 보이더라도 너무 많지 않게 유지
  • 목록형 화면은 한 줄 요약 + 보조 정보 + 상태 배지로 통일

4. 화면별 표현 원칙

같은 서비스지만, 화면의 역할은 분명히 다르게

PPOLO는 기록, 경쟁, 결과 확인의 목적이 달라 화면 밀도도 달라야 합니다.

접속 로딩 / 로그인

부드러운 진입만 보여주고, 사용자 판단을 요구하지 않습니다. 실패 시에는 이유를 짧게 보여줍니다.

홈 / 기록

대시보드 형태로 현재 상태를 먼저 보여주고, 상세 입력은 기록 화면으로 분리합니다.

경쟁 / 랭킹

대기실과 측정 중 화면을 분리하고, 실시간 랭킹과 최종 랭킹은 서로 다른 우선순위를 가집니다.

5. 상태 디자인

상태는 색보다 문구로 먼저 읽히게

대기 / 준비

입장 전, 경쟁 준비, 로딩처럼 사용자가 행동을 멈추고 확인하는 상태입니다.

진행 / 측정 중

운동 기록 또는 경쟁이 실제로 누적되는 구간입니다. 핵심 숫자가 계속 바뀝니다.

일시정지 / 경고

사용자 행동이 중단됐거나 검토가 필요한 상태입니다. 버튼 수를 줄입니다.

종료 / 취소 / 실격

되돌리기보다 결과를 읽는 단계입니다. 이때는 상태 설명을 명확히 둡니다.

6. 접근성 / 가독성

빠르게 읽을 수 있어야 한다

  • 주요 버튼은 큰 터치 영역을 유지합니다.
  • 같은 정보는 색만으로 구분하지 않고 텍스트도 함께 둡니다.
  • 화면마다 주요 행동 버튼은 1~2개 수준으로 제한합니다.
  • 워치와 모바일은 같은 상태 언어를 쓰되, 표현 밀도만 다르게 합니다.

7. 확인 기준

이 정의서가 타당한지 볼 때 체크할 항목

내용 부족 여부

화면 목적, 사용자, 주요 행동, 예외 상태가 빠진 부분이 없는지 본다.

구조 타당성

한 화면에 여러 목적이 섞이지 않고, 필요한 경우 별도 화면으로 분리돼 있는지 본다.

플로우 적합성

접속 → 로그인 → 홈 → 기록/경쟁 → 결과 확인으로 자연스럽게 이동하는지 본다.

8. 아직 확인할 항목

현재 초안에서 남겨둔 질문

  • 공지/이벤트를 홈에서 어느 비중으로 둘지
  • 경쟁방 생성에서 합의 결정의 기본값을 무엇으로 둘지
  • 로그인 오류와 네트워크 오류를 같은 화면 패턴으로 둘지
  • 워치 화면의 상태 요약 문구를 더 짧게 압축할지
