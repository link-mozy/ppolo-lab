# PPOLO 요구사항 정리본

> 이 문서는 현재까지 사용자 응답을 바탕으로 **확정된 요구사항**, **권장 해석**, **아직 모호한 항목**을 정리한 것이다.
> 구현 전에 이 문서를 기준으로 세부 설계를 진행한다.

---

## 1. 확정된 요구사항

### 1.1 로그인 / 계정
- MVP 소셜 로그인은 **Naver만 지원**한다.
- 사용자는 공개 프로필로 **닉네임과 프로필 사진**만 노출한다.
- 실명 및 기타 개인정보는 가능한 한 공개하지 않는다.
- 탈퇴 시 개인정보는 즉시 삭제한다.
- 분석 목적의 데이터는 익명화/압축 형태로 최소한만 보관한다.

### 1.2 모바일 / 워치
- 모바일 앱은 **iOS 우선**으로 시작한다.
- 스마트워치는 **Apple Watch 우선**으로 시작한다.
- MVP에서 모바일과 워치를 모두 개발하되, 순서는 **모바일 → 워치** 로 진행한다.

### 1.3 헬스 기록
- 필수 저장 항목:
  - 운동 부위
  - 운동 종목
  - 무게
  - 횟수
  - 세트 수
- 선택 항목:
  - 휴식 시간
  - 메모
  - RPE / 난이도
- 운동 종목은 **미리 정의된 마스터 목록** 으로 관리한다.
- 사용자가 요청하면 관리자가 목록을 추가/수정하는 방식으로 운영한다.
- 운동 부위는 최소 다음 수준으로 시작한다:
  - 가슴
  - 등
  - 어깨
  - 하체
  - 복근
  - 팔

### 1.4 런닝 기록
- 수동 입력 시 필수 항목은 **거리, 시간** 이다.
- 자동 입력 시에는 가능한 많은 센서 데이터를 수집한다.
- GPS 경로는 iOS/Android에서 공통적으로 가능한 최대 수준의 트랙을 수집한다.
- 거리와 페이스는 **기기 센서 기준을 우선** 하고, 서버는 보정/검증 역할을 한다.
- 런닝 중 일시정지는 필수 기능이다.

### 1.5 신체 변화 기록
- 저장 항목:
  - 키
  - 몸무게
  - 체지방률
  - 골격근량
  - 내장지방
  - 인바디 날짜
  - 메모
- 인바디 입력은 우선 **수동 입력** 으로 시작한다.
- 같은 날 여러 번 입력하는 경우에는 덮어쓰기 전 사용자에게 확인한다.
- 본인의 신체 정보는 수정 가능하다.

### 1.6 경쟁방
- 경쟁방은 **검색 입장 + 초대 입장** 을 모두 지원한다.
- 오픈된 경쟁방은 목록에 노출된다.
- 비공개 경쟁방 정책은 추가 확정이 필요하다.  
  현재 답변에는 "비밀번호 설정" 과 "비공개형은 비밀번호 없음" 이 함께 존재하므로 최종 정의가 필요하다.
- 결과 합의는 **동의/비동의 기록** 용도이며, 추후 내기 기능 같은 확장에 사용한다.
- 방장에게는 현재 완료 상태인 참가자가 누구인지 보여준다.
- 경쟁방 생성 필수값:
  - 방 제목
  - 목표 거리
  - 최대 인원
  - 마감 시간
  - 비밀방 여부
- 결과 합의 여부는 옵션이다.

### 1.7 경쟁 시작 / 종료
- 경쟁방의 시작과 참가자의 실제 기록 시작은 **별도 개념** 이다.
- 경쟁방은 모든 참가자가 준비완료가 되면 시작된다.
- 모든 참가자가 준비되지 않은 경우, 방장이 강제 시작할 수 있다.
- 강제 시작 시 준비되지 않은 참가자는 퇴출된다.
- 경쟁이 시작되더라도 각 참가자는 본인이 원하는 시간에 **기록 시작 버튼** 을 눌러 실제 런닝을 시작할 수 있다.
- 마감 시간은 종료 시간과 동일하다.
- 마감 이후에는 해당 경쟁에 기록 업로드가 불가하다.
- 경쟁 결과는 사용자가 수정할 수 없다.
- 경쟁은 수동 입력이 아니라 **기기로 측정된 값만** 저장한다.

### 1.8 경쟁 참여 시점
- 참가자는 경쟁방에 먼저 들어오고, 나중에 기록을 시작할 수 있다.
- 같은 경쟁방 안에서 참가자들이 서로 다른 시각에 기록을 시작할 수 있다.
- 마감 시간 내 시작만 허용된다.
- 마감 시간 내 완주 기록이 없는 경우는 **미완주 / 실격 성격의 상태** 로 처리한다.

### 1.9 일시정지 / 패널티
- 경쟁에서는 일시정지 허용 여부를 방장이 지정한다.
- 허용 시 최대 2분까지 허용한다.
- 일시정지 시간은 기본적으로 운동시간에서 제외한다.
- 최대 허용 시간을 초과하면 패널티가 적용된다.
- 앱이 백그라운드로 갔다고 해서 자동으로 일시정지로 보지는 않는다.
- 기록이 실제로 중지되어야만 일시정지로 본다.

### 1.10 실시간 랭킹
- 실시간 랭킹의 1순위는 **목표 도달 예상 시각(ETA)** 이다.
- 진행 중 / 완료 참가자만 랭킹 화면에 노출한다.
- 미시작자는 랭킹 화면에 노출하지 않는다.
- 1등과의 차이, 바로 앞 사람과의 차이는 별도 UI 가이드가 필요하다.
- 실시간 랭킹은 네트워크 기반 갱신이 가능해야 한다.

### 1.11 최종 랭킹
- 모든 참가자가 기록을 측정했으면 조기 최종 랭킹 확정이 가능하다.
- 한 명이라도 미시작이면 마감 시간에 최종 랭킹을 확정한다.
- 미완주자는 일반 순위보다 낮은 별도 상태로 관리한다.
- 실격은 꼴등보다 더 낮은 상태로 취급한다.
- 최종 랭킹 데이터는 저장해서 참가자가 나중에 확인 가능해야 한다.
- 실시간 랭킹의 중간 로그는 일정 기간 저장 후 삭제한다.

### 1.12 소셜 / 채팅
- 그룹 채팅을 지원한다.
- 친구 / 팔로우 / 차단 / 신고 기능을 모두 포함한다.
- 채팅 메시지는 우선 1개월 보관한다.

### 1.13 캘린더
- 캘린더는 운동 기록과 경쟁 기록을 모두 보여준다.
- 월간 뷰부터 시작한다.
- 일정 알림은 MVP에서는 넣지 않는다.

### 1.14 홈
- 홈 화면 초기 노출은 공지사항과 이벤트 위주다.
- 빈 화면에는 "데이터가 존재하지 않습니다." 문구를 기본 표시한다.

### 1.15 데이터 수정 / 삭제 / 보관
- 운동 기록은 수정 가능하다.
- 경쟁 결과는 수정 불가하다.
- 삭제된 데이터는 사용자에게 복구 불가, 다만 로그로는 일부 추적 가능해야 한다.
- 기록 보관 기간은 별도 정책이 필요하다.

### 1.16 추천 시스템
- 추천 시스템은 추후 기능으로 미룬다.
- 추천 대상은 운동 종목과 운동 빈도다.
- 데이터는 최대한 많이 활용한다.

### 1.17 MVP 우선순위
- 반드시 포함:
  - 로그인
  - 운동 기록
  - 경쟁(달리기)
- 제외:
  - 채팅
  - 캘린더
- 시작 화면 우선순위:
  1. 로그인
  2. 홈
  3. 훈련일지
  4. 대결

## 2. 권장 해석 / 구현 가이드

### 2.1 한 사용자는 하나의 계정만?
가능하다.

권장 방식:
- 서비스 내부 계정은 1개만 허용
- MVP에서는 Naver 계정의 고유 식별자를 내부 사용자 키로 사용
- 이메일/전화번호는 계정 복구 및 안전장치로만 사용
- 현실적으로 "한 사람=한 계정"을 100% 보장하긴 어려우므로, 서비스 내부 계정 수만 1개로 제한하는 방식이 현실적이다

### 2.2 GPS 수준
- "지도 수준"의 경로는 일반적인 모바일 위치 API로 충분히 가능하다.
- 다만 이는 지도/경로 표시용의 소비자 등급 정확도이며, 측량급 정밀도는 아니다.
- 권장 저장값:
  - 위도/경도
  - timestamp
  - speed
  - accuracy
  - altitude
  - heading

### 2.3 거리 / 페이스 계산 우선순위
권장 순서:
1. 기기 센서 원본
2. 서버 검증/정규화
3. 서버 보정값 저장

즉, **원본은 보존하고 정규화된 값을 별도 저장** 하는 방식이 가장 안전하다.

### 2.4 경쟁 랭킹
- 실시간 랭킹은 ETA 중심이 적합하다.
- 최종 랭킹은 마감 기준의 확정 데이터로 계산한다.
- 미시작자는 실시간 랭킹에서 숨긴다.
- 실격은 별도 영역으로 분리한다.

### 2.5 자동/수동 혼합 데이터
- 수동 기록과 자동 기록은 같은 도메인에 저장하되, `source` 값을 분리한다.
- `manual`, `device`, `watch`, `server_normalized` 같은 구분이 필요하다.

## 3. 아직 모호한 항목

### 3.1 경쟁방 비밀번호 정책
사용자 답변에 상충이 있다.

- 한 답변에서는 "비밀번호를 설정하면 비공개방" 으로 읽힌다.
- 다른 답변에서는 "비공개형은 비밀번호 없는 형태" 라고 되어 있다.

이 부분은 구현 전에 반드시 하나로 확정해야 한다.

질문 예:
- 비공개방은 비밀번호가 있는가?
- 비공개방은 초대 전용인가?
- 비공개방은 검색 가능하지만 입장 시 초대 토큰이 필요한가?

### 3.2 일시정지 패널티의 정확한 계산식
현재 답변은 다음처럼 읽힌다.

- 기본 허용 일시정지 시간은 2분
- 초과하면 패널티

하지만 아래가 명확하지 않다.
- 초과분만 두 배로 계산하는지
- 전체 pause 시간에 가중치를 주는지
- 초과한 시점부터 1초 pause = 2초 패널티인지

이 부분은 수식으로 확정해야 한다.

### 3.3 최종 랭킹에서 상태별 UI 표현
권장안은 다음과 같다.
- `finished`: 공식 순위
- `expired`: 미완주/미기록 별도 구역
- `dnf`: 포기 별도 구역
- `disqualified`: 실격 별도 구역, 가장 아래

하지만 실제 화면에서 숫자 순위로 보여줄지, 섹션 분리로 보여줄지는 최종 결정이 필요하다.

### 3.4 경쟁 시작 버튼 흐름
현재는 개념적으로는 정리되었지만, 실제 화면 전환과 버튼 순서는 더 세부화가 필요하다.

예:
- 방 입장
- 대기실
- 준비완료
- 경쟁방 시작
- 개인 기록 시작
- 일시정지 / 재개 / 종료
- 마감 후 결과

이 흐름을 상태 다이어그램으로 확정하는 것이 좋다.

### 3.5 홈 화면 정보 밀도
홈에 공지와 이벤트만 우선 보여주기로 했지만,
카드형/피드형 중 어떤 레이아웃이 더 적절한지 추가 검토가 필요하다.

## 6. 결론

현재 PPOLO는 MVP 방향이 꽤 선명하다.
핵심은 다음이다.
- Naver 로그인
- iOS / Apple Watch 우선
- 런닝 중심 경쟁
- ETA 중심 실시간 랭킹
- 마감 시간 기준 최종 랭킹
- 기록은 수동/자동을 함께 지원하되 자동이 우선
- 개인정보는 최소 공개

다만, **경쟁방 비밀번호 정책** 과 **일시정지 패널티 수식** 은 아직 확정이 필요하다.
