# PPOLO 요구사항 정리본

> 이 문서는 현재까지 사용자 응답을 바탕으로 **확정된 요구사항**, **권장 해석**, **아직 모호한 항목**을 정리한 것이다.
> 구현 전에 이 문서를 기준으로 세부 설계를 진행한다.

---

## 1. 확정된 요구사항

### 1.1 로그인 / 계정
- MVP 소셜 로그인은 **Naver만 지원**한다.
- 사용자는 공개 프로필로 **닉네임과 프로필 사진**만 노출한다.
- 실명 및 기타 개인정보는 가능한 한 공개하지 않는다.
- 탈퇴 시 개인정보는 즉시 삭제한다.
- 분석 목적의 데이터는 익명화/압축 형태로 최소한만 보관한다.

### 1.2 모바일 / 워치
- 모바일 앱은 **iOS 우선**으로 시작한다.
- 스마트워치는 **Apple Watch 우선**으로 시작한다.
- MVP에서 모바일과 워치를 모두 개발하되, 순서는 **모바일 → 워치** 로 진행한다.
- 워치는 입력 단말이 아니라 **최소한의 리모컨 + 상태 모니터링 화면** 으로 설계한다.

### 1.3 헬스 기록
- 필수 저장 항목:
  - 운동 부위
  - 운동 종목
  - 무게
  - 횟수
  - 세트 수
- 선택 항목:
  - 휴식 시간
  - 메모
  - RPE / 난이도
- 운동 종목은 **미리 정의된 마스터 목록** 으로 관리한다.
- 사용자가 요청하면 관리자가 목록을 추가/수정하는 방식으로 운영한다.
- 운동 부위는 최소 다음 수준으로 시작한다:
  - 가슴
  - 등
  - 어깨
  - 하체
  - 복근
  - 팔

### 1.4 런닝 기록
- 수동 입력 시 필수 항목은 **거리, 시간** 이다.
- 자동 입력 시에는 가능한 많은 센서 데이터를 수집한다.
- GPS 경로는 iOS/Android에서 공통적으로 가능한 최대 수준의 트랙을 수집한다.
- 거리와 페이스는 **기기 센서 기준을 우선** 하고, 서버는 보정/검증 역할을 한다.
- 런닝 중 일시정지는 필수 기능이다.

### 1.5 신체 변화 기록
- 저장 항목:
  - 키
  - 몸무게
  - 체지방률
  - 골격근량
  - 내장지방
  - 인바디 날짜
  - 메모
- 인바디 입력은 우선 **수동 입력** 으로 시작한다.
- 신체 변화 기록은 최신 값 기준으로 관리하며, 같은 날 여러 번 입력하는 경우에는 덮어쓰기 전 사용자에게 확인한다.
- 본인의 신체 정보는 수정 가능하다.

### 1.5.1 헬스 기록
- 헬스 기록은 **여러 번 입력 가능** 해야 한다.
- 같은 날 여러 번 입력해도 기존 기록을 덮어쓰지 않고 각각 독립된 기록으로 저장한다.
- 헬스 기록과 신체 변화 기록은 서로 다른 도메인이다.

### 1.6 경쟁방
- 경쟁방은 **검색 입장 + 초대 입장** 을 모두 지원한다.
- 오픈된 경쟁방은 목록에 노출된다.
- 경쟁방에는 별도의 `초대방` 타입이 없고, 방 내부에 **특정 사람을 초대하는 기능**만 있다.
- 초대는 방의 타입을 바꾸지 않으며, **특정 사용자에게 입장을 알리는 알림 기능**이다.
- 초대받은 사용자는 **초대 알림을 직접 탭해서** 입장 흐름을 시작한다.
- 초대받은 사용자도 비공개 경쟁방이라면, **사전에 알고 있는 동일한 비밀번호를 입력해야만** 참가할 수 있다.
- 비공개 경쟁방은 **생성 시 방장이 비밀번호를 직접 입력** 한다.
- 입장 시 사용자는 입력한 비밀번호가 저장된 비밀번호 문자열과 **완전히 일치해야만** 참가할 수 있다.
- 비밀번호는 개인정보가 아니므로, 현재 정책에서는 별도의 암호화/해시 요구를 두지 않는다.
- 비밀번호 검증은 단순한 문자열 비교로 처리한다.
- 초대 기능은 `친구/팔로우/검색된 사용자` 중에서 대상을 선택해 보낼 수 있다.
- 초대는 여러 명에게 보낼 수 있으나, 각 초대의 수락/거절은 사용자별로 독립적으로 처리한다.
- 결과 합의는 **동의/비동의 기록** 용도이며, 추후 내기 기능 같은 확장에 사용한다.
- 방장에게는 현재 완료 상태인 참가자가 누구인지 보여준다.
- 경쟁방 생성 필수값:
  - 방 제목
  - 목표 거리
  - 최대 인원
  - 마감 시간
  - 비밀방 여부
  - 비밀방인 경우 비밀번호
- 결과 합의 여부는 옵션이다.

### 1.7 경쟁 시작 / 종료
- 경쟁방의 시작과 참가자의 실제 기록 시작은 **별도 개념** 이다.
- 참가자가 대기실에 들어오면 즉시 **경쟁방 입장 완료** 상태로 간주한다.
- 경쟁방 입장 완료는 **대기실에 입장한 상태** 를 뜻하며, 별도의 준비 버튼은 두지 않는다.
- 경쟁방은 최대 인원이 모두 차면 **자동 시작** 한다.
- 최대 인원이 차지 않았더라도 방장은 **현재 참가 인원 기준으로 시작** 할 수 있다.
- 경쟁 시작은 **방 상태 전환 이벤트** 이고, 기록 측정은 **참가자별 상태 전환** 이다.
- 자동 시작 또는 방장 시작이 발생하면 방 상태는 `경쟁 준비`에서 `경쟁 중`으로 전환된다.
- `경쟁 준비`는 **경쟁 시작 전** 상태이며, 참가자들은 대기실에 있다.
- `경쟁 중`은 **경쟁 시작 후** 상태이며, 참가자들은 `측정 대기`, `측정 중`, `측정 완료` 상태를 오간다.
- 각 참가자가 실제 기록을 시작하면 해당 참가자는 `측정 중` 상태로 전환된다.
- 각 참가자가 기록을 끝내면 해당 참가자는 `측정 완료` 상태로 전환된다.
- 모든 참가자가 `측정 완료` 상태가 되면 경쟁은 **경쟁 종료 상태** 로 전환된다.
- 마감 시간은 종료 시간과 동일하다.
- 마감 이후에는 해당 경쟁에 기록 업로드가 불가하다.
- 경쟁 결과는 사용자가 수정할 수 없다.
- 경쟁은 수동 입력이 아니라 **기기로 측정된 값만** 저장한다.
- 경쟁이 진행 중인 사용자는 그 경쟁이 끝날 때까지 **다른 경쟁방에 참가할 수 없다**.

### 1.8 경쟁 참여 시점
- 참가자는 경쟁방에 먼저 들어오고, 나중에 기록을 시작할 수 있다.
- 같은 경쟁방 안에서 참가자들이 서로 다른 시각에 기록을 시작할 수 있다.
- 마감 시간 내 시작만 허용된다.
- 마감 시간 시점에 아직 측정을 시작하지 않은 참가자는 `DNS` 로 처리한다.
- 마감 시간 시점에 측정 중인 참가자는 기록은 유지하되 최종 순위는 `DNF` 로 처리한다.
- 마감 시간 시점에 중도 종료한 참가자는 `DNF` 로 처리한다.
- 방장이 설정한 마감 시간의 **1시간 전까지도 경쟁이 시작되지 않으면**, 해당 경쟁은 성사되지 않은 것으로 보고 안내 메시지를 보여준 뒤 **경쟁방을 종료(취소)** 한다.
- 안내 메시지 문구는 예를 들어 **"오늘의 경기는 성사되지 않았습니다. 콜로세움의 문을 닫습니다."** 처럼 로마 경기장 분위기에 맞게 표현할 수 있다.

### 1.8.1 경쟁 탭 진입 규칙
- 하단 네비게이션의 **경쟁** 버튼은 기본적으로 경쟁 기능의 진입점이다.
- 사용자가 **이미 진행 중인 경쟁** 이 있으면, 경쟁 버튼은 경쟁방 목록 대신 **현재 진행 중인 경쟁 화면** 으로 바로 이동한다.
- 진행 중인 경쟁이 없을 때만 경쟁방 목록/검색/초대 진입 화면을 보여준다.
- 따라서 진행 중인 경쟁이 있는 동안에는 경쟁 탭에서 다른 경쟁방을 새로 찾거나 참가하는 흐름을 보여주지 않는다.

### 1.8.2 경쟁 시작 흐름 다이어그램 문장
- `경쟁 없음` → 사용자가 `경쟁` 탭을 누른다 → `경쟁방 목록` 으로 이동한다.
- `진행 중인 경쟁 있음` → 사용자가 `경쟁` 탭을 누른다 → `현재 진행 중인 경쟁 화면` 으로 즉시 이동한다.
- `현재 진행 중인 경쟁 화면` → 방 상태는 `경쟁 준비` 이다.
- `방장 시작` 또는 `자동 시작 조건 충족` → 방 상태는 `경쟁 중` 으로 전환된다.
- `경쟁 중` → 사용자가 `측정 시작` 버튼을 누른다 → 해당 참가자는 `측정 중` 이 된다.
- `측정 중` → 사용자가 기록을 마친다 → 해당 참가자는 `측정 완료` 가 된다.
- `모든 참가자 = 측정 완료` → 방 상태는 `경쟁 종료` 로 전환된다.
- `마감 1시간 전까지 시작되지 않음` → 경쟁은 성사되지 않은 것으로 판단하고 `경쟁 취소` 처리한다.
- `경쟁 진행 중인 참가자` → 해당 경쟁이 종료될 때까지 다른 경쟁방에 참가할 수 없다.

### 1.8.3 경쟁 시작 버튼 흐름
- 사용자는 하단 `경쟁` 버튼을 눌러 경쟁방 목록으로 이동한다.
- 사용자는 공개 경쟁방을 선택하고 입장 확인 팝업에서 확인을 누른다.
- 입장 직후 참가자는 대기실에 있으며 상태는 `측정 대기` 이다.
- 모든 참가자의 입장이 완료되거나 방장이 시작하면 방 상태는 `경쟁 중` 이 된다.
- 참가자는 마감 시간 내 원할 때 `측정 시작` 버튼을 눌러 `측정 중` 상태로 전환한다.
- 참가자는 측정이 끝나면 `측정 완료` 버튼을 눌러 `측정 완료` 상태로 전환한다.
- 일시정지 허용 옵션이 설정된 경우에만 `일시정지` / `재개` 버튼이 노출된다.
- 마감 시간이 되면 결과를 확정하고 최종 랭킹을 보여준다.

### 1.9 일시정지 / 패널티
- 경쟁에서는 일시정지 허용 여부와 **누적 무료 일시정지 시간** 을 방장이 지정한다.
- 누적 무료 일시정지 시간은 **0초~300초(5분)** 범위에서 설정 가능하다.
- 기본값은 `0초` 이며, `0초` 는 일시정지 비활성화로 본다.
- 입력값은 양의 정수만 허용하며, `0초` 는 예외적으로 비활성화 표현으로 허용한다.
- 일시정지 시간은 경쟁 전체 기준의 **누적 총합** 으로 계산한다.
- 일시정지는 여러 번 나누어 사용할 수 있다.
- 누적 무료 일시정지 시간을 초과한 pause 시간은 **1:1로 유효시간에 반영** 된다.
- 추가 가중 패널티(예: 2배)는 적용하지 않는다.
- 일시정지 허용 시간이 `0초` 인 경우에는 일시정지 버튼을 노출하지 않는다.
- 앱이 백그라운드로 갔다고 해서 자동으로 일시정지로 보지는 않는다.
- 기록이 실제로 중지되어야만 일시정지로 본다.
- 일시정지 무효 판정의 세부 기준은 MVP 초안으로 두고, 운영하면서 채운다.
- 일시정지 중 이동량이 기준치를 넘으면 해당 일시정지는 **무효 처리** 하고 자동으로 해제한다.
- 무효 처리 시 사용자에게 **"일시정지가 해제되었습니다"** 또는 **"이동이 감지되어 일시정지가 무효 처리되었습니다"** 같은 경고를 보여준다.
- 무효 처리된 구간은 일시정지 시간에 포함하지 않는다.

### 1.10 실시간 랭킹
- 실시간 랭킹의 1순위는 **목표 도달 예상 시각(ETA)** 이다.
- 진행 중 / 완료 참가자만 랭킹 화면에 노출한다.
- 미시작자는 랭킹 화면에 노출하지 않는다.
- 1등과의 차이, 바로 앞 사람과의 차이는 별도 UI 가이드가 필요하다.
- 실시간 랭킹은 네트워크 기반 갱신이 가능해야 한다.

### 1.11 최종 랭킹
- 모든 참가자가 기록을 측정했으면 조기 최종 랭킹 확정이 가능하다.
- 한 명이라도 미시작이면 마감 시간에 최종 랭킹을 확정한다.
- 미완주자는 일반 순위보다 낮은 별도 상태로 관리한다.
- 실격은 꼴등보다 더 낮은 상태로 취급한다.
- 최종 랭킹 데이터는 저장해서 참가자가 나중에 확인 가능해야 한다.
- 실시간 랭킹의 중간 로그는 일정 기간 저장 후 삭제한다.

### 1.12 소셜 / 채팅
- 그룹 채팅을 지원한다.
- 친구 / 팔로우 / 차단 / 신고 기능을 모두 포함한다.
- 채팅 메시지는 우선 1개월 보관한다.

### 1.13 캘린더
- 캘린더는 운동 기록과 경쟁 기록을 모두 보여준다.
- 월간 뷰부터 시작한다.
- 일정 알림은 MVP에서는 넣지 않는다.

### 1.14 홈
- 홈 화면 초기 노출은 공지사항과 이벤트 위주다.
- 빈 화면에는 "데이터가 존재하지 않습니다." 문구를 기본 표시한다.

### 1.15 데이터 수정 / 삭제 / 보관
- 운동 기록은 수정 가능하다.
- 경쟁 결과는 수정 불가하다.
- 삭제된 데이터는 사용자에게 복구 불가, 다만 로그로는 일부 추적 가능해야 한다.
- 기록 보관 기간은 별도 정책이 필요하다.

### 1.16 추천 시스템
- 추천 시스템은 추후 기능으로 미룬다.
- 추천 대상은 운동 종목과 운동 빈도다.
- 데이터는 최대한 많이 활용한다.

### 1.17 MVP 우선순위
- 반드시 포함:
  - 로그인
  - 운동 기록
  - 경쟁(달리기)
- 제외:
  - 채팅
  - 캘린더
- 시작 화면 우선순위:
  1. 로그인
  2. 홈
  3. 훈련일지
  4. 대결

## 2. 권장 해석 / 구현 가이드

### 2.1 한 사용자는 하나의 계정만?
가능하다.

권장 방식:
- 서비스 내부 계정은 1개만 허용
- MVP에서는 Naver 계정의 고유 식별자를 내부 사용자 키로 사용
- 이메일/전화번호는 계정 복구 및 안전장치로만 사용
- 현실적으로 "한 사람=한 계정"을 100% 보장하긴 어려우므로, 서비스 내부 계정 수만 1개로 제한하는 방식이 현실적이다

### 2.2 GPS 수준
- "지도 수준"의 경로는 일반적인 모바일 위치 API로 충분히 가능하다.
- 다만 이는 지도/경로 표시용의 소비자 등급 정확도이며, 측량급 정밀도는 아니다.
- 권장 저장값:
  - 위도/경도
  - timestamp
  - speed
  - accuracy
  - altitude
  - heading

### 2.3 거리 / 페이스 계산 우선순위
권장 순서:
1. 기기 센서 원본
2. 서버 검증/정규화
3. 서버 보정값 저장

즉, **원본은 보존하고 정규화된 값을 별도 저장** 하는 방식이 가장 안전하다.

### 2.4 경쟁 랭킹
- 실시간 랭킹은 ETA 중심이 적합하다.
- 최종 랭킹은 **완주한 참가자만** 대상으로 계산한다.
- 최종 랭킹의 비교 기준은 각 참가자의 **측정 시작 시점부터 측정 종료 시점까지의 기록**이다.
- 마감 기준 시점에 완주하지 못한 참가자는 최종 랭킹 대상에서 제외하고 별도 결과 상태로 분리한다.
- 미시작자는 실시간 랭킹에서 숨긴다.
- 실격은 별도 영역으로 분리한다.

### 2.5 자동/수동 혼합 데이터
- 수동 기록과 자동 기록은 같은 도메인에 저장하되, `source` 값을 분리한다.
- `manual`, `device`, `watch`, `server_normalized` 같은 구분이 필요하다.

### 2.6 경쟁방 비밀번호 입력/검증
- 경쟁방 생성 시 방장이 비밀번호 텍스트를 직접 입력할 수 있다.
- 입장 시 사용자가 입력한 비밀번호 문자열이 저장된 문자열과 **완전히 일치해야만** 입장할 수 있다.
- 비밀번호 검증은 단순 문자열 비교로 처리한다.
- 비밀번호는 개인정보가 아니므로, 현재 정책에서는 별도의 암호화/해시 요구를 두지 않는다.

### 2.7 최종 랭킹 화면의 상태별 UI 표현
- 최종 랭킹의 기본 표시는 `1위, 2위, 3위...` 형태의 **숫자 순위 리스트**로 한다.
- 숫자 순위 리스트 아래에는 `순위 외 결과` 섹션을 둔다.
- `순위 외 결과` 섹션은 기본적으로 접힌 상태로 노출한다.
- 사용자가 `순위 외 결과` 섹션을 탭하면 펼쳐져서 `dns`, `dnf`, `disqualified` 결과를 확인할 수 있다.
- `순위 외 결과` 내부는 카드형 또는 리스트형으로 표현할 수 있으나, 상태별 구분이 분명해야 한다.
- `disqualified`는 `순위 외 결과` 안에서도 가장 아래 상태로 취급한다.

### 2.8 경쟁 시작 버튼 흐름
- 사용자는 하단 `경쟁` 버튼을 눌러 경쟁방 목록으로 이동한다.
- 사용자는 공개 경쟁방을 선택하고 입장 확인 팝업에서 확인을 누른다.
- 입장 직후 참가자는 대기실에 있으며 상태는 `측정 대기` 이다.
- 모든 참가자의 입장이 완료되거나 방장이 시작하면 방 상태는 `경쟁 중` 이 된다.
- 참가자는 마감 시간 내 원할 때 `측정 시작` 버튼을 눌러 `측정 중` 상태로 전환한다.
- 참가자는 측정이 끝나면 `측정 완료` 버튼을 눌러 `측정 완료` 상태로 전환한다.
- 일시정지 허용 옵션이 설정된 경우에만 `일시정지` / `재개` 버튼이 노출된다.
- 마감 시간이 되면 결과를 확정하고 최종 랭킹을 보여준다.

### 2.9 실시간 랭킹 ETA 설정
- 실시간 랭킹의 `ETA` 는 누적 평균 ETA와 최근 구간 ETA를 조합하여 계산한다.
- `ETA` 계산 비율은 설정값으로 관리한다.
- `avg_weight` 와 `recent_weight` 의 합은 항상 `100` 이다.
- MVP 초기값은 `avg_weight = 100`, `recent_weight = 0` 으로 설정한다.
- 이후 운영 과정에서 `80:20`, `60:40` 과 같이 최근 구간 반영 비율을 조정할 수 있다.
- 최근 구간 계산에 사용할 시간 범위와 최소 거리 기준은 별도 설정값으로 관리한다.
- `측정 대기` 상태에서는 `ETA` 를 표시하지 않거나 `-` 로 표시한다.
- `DNS`, `DNF`, `disqualified` 상태는 `ETA` 대신 결과 상태로 표시한다.
