# PPOLO 경쟁 상태 머신 명세

> 이 문서는 PPOLO 경쟁방의 *방 상태*와 *참가자 상태*를 분리해서 정의한다.
> 목표는 시작/대기/진행/종료/취소의 경계를 서버 기준으로 명확하게 고정하는 것이다.

---

## 1. 문서 목적

경쟁 기능은 다음 두 개의 상태계를 반드시 분리한다.

- **방(Room) 상태**: 경쟁방 전체의 생명주기
- **참가자(Participant) 상태**: 각 사용자의 기록 진행 상태

이 문서는 다음을 명확히 한다.

- 언제 방이 시작/종료/취소되는지
- 참가자가 언제 측정을 시작/중지/완료하는지
- 마감 시간, 자동 시작, DNS/DNF 처리 시점
- 일시정지 허용 시간과 초과분 처리 방식
- 여러 참가자가 서로 다른 시각에 시작하는 경우의 규칙

## 3. 기본 원칙

1. **방 상태와 참가자 상태는 독립적이다.**
   - 방이 `경쟁중`이어도 참가자는 `측정 대기`일 수 있다.
   - 참가자가 `측정 완료`여도 방은 아직 `경쟁중`일 수 있다.

2. **시작 시간과 입장 시간은 다르다.**
   - 참가자는 방에 먼저 입장할 수 있다.
   - 실제 기록 시작은 나중에 할 수 있다.

3. **서버가 최종 판정한다.**
   - 클라이언트가 보여주는 상태는 표시용이다.
   - 마감, 시작 가능 여부, DNS/DNF, 취소 여부는 서버가 최종 확정한다.

4. **마감 시간은 서버 시각 기준이다.**
   - 클라이언트 로컬 시각은 보조 정보다.
   - 업로드 가능 여부는 서버 시간으로 판정한다.

5. **방장은 방 상태를 바꿀 수 있지만, 참가자 상태는 각자별로 바뀐다.**
   - 방장은 방 시작을 트리거할 수 있다.
   - 각 참가자의 측정 시작/종료는 해당 참가자의 행위로 기록된다.

---

## 4. 방 상태 정의

### 4.1 `competition_ready` = `대기중`

방이 생성되었고, 아직 경쟁이 시작되지 않은 상태다.

#### 특징
- 참가자는 입장할 수 있다.
- 참가자는 대기실에 있을 수 있다.
- 참가자는 아직 측정을 시작하지 않았다.
- 방장은 시작 조건을 확인할 수 있다.
- 최대 인원 충족 또는 방장 수동 시작으로 다음 상태로 이동한다.

#### 허용 동작
- 참가자 입장
- 초대 발송
- 방 정보 조회
- 방장 시작
- 자동 시작 조건 충족

#### 금지 동작
- 이미 시작된 참가자의 기록을 이 상태에서 인정하지 않는다.
- 마감 이후 새 참가자 기록 시작은 허용하지 않는다.

---

### 4.2 `competition_running` = `경쟁중`

경쟁이 실제로 진행 중인 상태다.

#### 특징
- 참가자별 기록이 시작될 수 있다.
- 참가자는 `측정 대기`, `측정 중`, `일시정지 중`, `측정 완료`를 오간다.
- 실시간 랭킹 계산 대상이 활성화된다.

#### 허용 동작
- 참가자 측정 시작
- 참가자 일시정지 / 재개
- 참가자 측정 종료
- 실시간 랭킹 갱신

#### 금지 동작
- 마감 이후 새 기록 시작
- 완료된 기록 수정
- 종료 후 재진입을 통한 재측정

---

### 4.3 `finished` = `경쟁 종료`

모든 판정이 끝나 최종 랭킹이 확정된 상태다.

#### 특징
- 최종 랭킹이 저장된다.
- 참가자 상태는 더 이상 변경되지 않는다.
- 결과 조회만 가능하다.

#### 종료 조건
- 모든 참가자가 `측정 완료` 상태가 되었을 때
- 또는 마감 시각에 도달해 최종 판정이 가능해졌을 때

---

### 4.4 `cancelled` = `경쟁 취소`

경쟁이 성사되지 않았거나 운영 규칙상 취소된 상태다.

#### 특징
- 결과 랭킹을 생성하지 않는다.
- 참가자 상태는 취소 사유 확인용으로만 보관한다.

#### 대표 취소 사유
- `deadline_at - 1시간` 시점까지 경쟁이 시작되지 않음
- 운영자 취소
- 유효 참가자 수가 정책상 최소치 미달

---

## 5. 참가자 상태 정의

### 5.1 `joined_waiting` = `측정 대기`

참가자는 방에 들어와 있지만 아직 측정을 시작하지 않았다.

#### 특징
- 대기실에 들어온 직후의 기본 상태다.
- 방이 `경쟁중`이더라도 참가자는 이 상태일 수 있다.
- 마감 시점까지 시작하지 않으면 `DNS` 판정 대상이 된다.

#### 허용 동작
- 측정 시작
- 방 나가기
- 상태 조회

---

### 5.2 `measuring` = `측정 중`

실제 기록이 진행 중인 상태다.

#### 특징
- 거리/시간/페이스가 누적된다.
- 랭킹 계산의 중심 상태다.
- 마감 시점에 이 상태면 최종적으로 `DNF` 또는 유사 결과 판정을 받을 수 있다.

#### 허용 동작
- 일시정지
- 측정 종료
- 네트워크 재동기화

---

### 5.3 `paused` = `일시정지 중`

기록이 일시적으로 멈춘 상태다.

#### 특징
- 누적 일시정지 시간이 계산된다.
- 허용 시간 내라면 패널티 없이 처리한다.
- 허용 시간을 초과하면 초과분이 순위 비교에 반영된다.

#### 허용 동작
- 재개
- 측정 종료

#### 주의
- 앱이 백그라운드에 갔다고 자동으로 `paused`로 처리하지 않는다.
- 실제 기록 중지가 발생해야만 `paused`로 본다.

---

### 5.4 `measured` = `측정 완료`

참가자가 기록을 끝내고 결과가 확정 대기 또는 확정 상태로 들어간 상태다.

#### 특징
- 더 이상 거리/시간이 증가하지 않는다.
- 최종 순위 계산 대상이 된다.
- 방의 종료 조건이 될 수 있다.

---

## 6. 상태 전이 요약

### 6.1 방 상태 전이

- `competition_ready` → `competition_running`
  - 방장 시작
  - 최대 인원 충족에 따른 자동 시작

- `competition_running` → `finished`
  - 모든 참가자 `측정 완료`
  - 또는 마감 시각에 도달해 최종 판정 가능

- `competition_ready` → `cancelled`
  - `deadline_at - 1시간`까지 시작되지 않음
  - 운영 취소

- `competition_running` → `cancelled`
  - 운영 취소
  - 심각한 데이터 무결성 문제

---

### 6.2 참가자 상태 전이

- `joined_waiting` → `measuring`
  - 참가자가 `측정 시작`을 누름
  - 또는 워치/기기 시작 이벤트가 서버에 반영됨

- `measuring` → `paused`
  - 참가자가 일시정지를 누름
  - 일시정지 허용 정책이 활성화되어 있어야 함

- `paused` → `measuring`
  - 참가자가 재개를 누름

- `measuring` → `measured`
  - 참가자가 종료
  - 또는 유효한 종료 이벤트가 서버에 반영됨

- `joined_waiting` → `DNS`
  - 마감 시각까지 시작하지 않음

- `measuring` → `DNF`
  - 마감 시각 도달 시 아직 종료되지 않음
  - 중도 포기 또는 기록 불완전

---

## 7. 마감 시간 규칙

### 7.1 시작 가능 시점

- 참가자는 `deadline_at` 이전에만 측정을 시작할 수 있다.
- 시작 시점이 `deadline_at`과 같거나 이후면 시작 불가다.

### 7.2 업로드 가능 시점

- 업로드는 서버 시간 기준으로 판정한다.
- `deadline_at` 이후 도착한 기록은 원칙적으로 인정하지 않는다.

### 7.3 마감 1시간 전 취소 규칙

- `deadline_at - 1시간` 시점까지 경쟁이 시작되지 않으면 경쟁은 성사되지 않은 것으로 본다.
- 이 경우 방 상태는 `cancelled`로 전환한다.
- 취소 안내 메시지를 사용자에게 보여준다.

---

## 8. 여러 참가자가 서로 다른 시각에 시작하는 경우

경쟁방 입장 시각과 실제 측정 시작 시각은 독립적이다.

### 허용되는 시나리오
- 참가자 A는 10:00에 입장하고 10:05에 시작
- 참가자 B는 10:20에 입장하고 10:25에 시작
- 둘 다 `deadline_at` 이전에 시작하면 유효하다

### 판정 원칙
- 각 참가자의 랭킹은 자신의 시작 시점 이후 누적 기록을 기준으로 계산한다.
- 참가자 간 출발 시각이 달라도 같은 방 안에서 경쟁 가능하다.
- 단, 마감 이후 시작은 불가하다.

---

## 9. 일시정지 시간 규칙

### 9.1 기본값

- `allowed_pause_seconds = 0`이면 일시정지 기능은 비활성화다.
- 허용 시간이 0보다 크면 누적 총합으로 계산한다.

### 9.2 계산 방식

- 일시정지 시간은 여러 구간의 합이다.
- 허용 시간 내 구간은 패널티가 없다.
- 허용 시간 초과분은 순위 비교에 반영한다.

### 9.3 무효 처리

- 일시정지 중 이동량이 기준치를 넘으면 해당 일시정지는 무효 처리된다.
- 무효 처리된 시간은 일시정지 시간에 포함하지 않는다.
- 무효 처리 시 사용자에게 경고를 보여준다.

---

## 10. DNS / DNF / 실격 분기

### DNS

- 마감 시각까지 시작하지 않음
- 참가자는 방에 있었지만 실제 측정을 시작하지 못함

### DNF

- 측정을 시작했지만 끝내지 못함
- 마감 시각 도달 시 측정 중 상태
- 중도 포기

### 실격

- 규칙 위반
- 데이터 조작 의심
- 운영자 판정

### 우선순위

- 실격은 DNS/DNF보다 더 낮은 상태다.
- 최종 랭킹의 `순위 외 결과` 섹션에 포함한다.

---

## 11. 시나리오 매트릭스

### 11.1 방 상태 × 참가자 상태

- `competition_ready` + `joined_waiting`
  - 정상 대기

- `competition_running` + `joined_waiting`
  - 경쟁은 시작됐지만 해당 참가자는 아직 시작 전

- `competition_running` + `measuring`
  - 정상 진행

- `competition_running` + `paused`
  - 일시정지 중

- `competition_running` + `measured`
  - 해당 참가자 완료

- `finished` + `measured`
  - 최종 결과 확정

- `finished` + `joined_waiting`
  - DNS 확정

- `finished` + `measuring`
  - DNF 확정 또는 예외 처리

- `cancelled` + any
  - 결과 없음, 취소 사유만 표시

### 11.2 주요 경계 상황

- 마감 직전 시작
- 마감 시각에 정확히 시작
- 일시정지 허용 시간 정확히 소진
- 일시정지 무효 처리
- 시작은 했지만 완료 전에 마감 도달
- 참가자는 입장했으나 시작하지 못함

---

## 12. 서버 판정 우선순위

서버는 다음 순서로 상태를 판정한다.

1. 방 취소 여부
2. 방 종료 여부
3. 참가자 시작 여부
4. 참가자 완료 여부
5. DNS / DNF / 실격 여부
6. 최종 순위 확정

클라이언트는 위 상태를 캐시하거나 표시할 수 있지만, 최종 상태를 덮어쓸 수 없다.

## 15. 결론

PPOLO 경쟁 기능은 다음처럼 이해하면 된다.

- **방은 하나의 생명주기**를 가진다.
- **참가자는 각자 독립된 측정 생명주기**를 가진다.
- **마감과 판정은 서버가 결정**한다.
- **입장 시각과 시작 시각은 다를 수 있다.**
- **일시정지는 누적 합산하고, 초과분은 순위에 반영**한다.
- **마감 이후 시작은 금지**한다.
